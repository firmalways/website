ถ้าข้อมูลหลุดไปถึงมือมิจฉาชีพ จะเกิดอะไรขึ้น

ข้อความที่วางลงในแชต AI ส่วนตัวอาจถูกเก็บไว้นอกองค์กร หากรั่วไหลจากบัญชีที่ถูกแฮ็ก ระบบของผู้ให้บริการ หรือลิงก์แชร์บทสนทนา มิจฉาชีพจะไม่ต้องเดาอีกต่อไป เพราะมีข้อมูลจริงไว้สร้างความน่าเชื่อถือ

1แอบอ้างเป็นลูกหรือญาติ

  • ชื่อ-นามสกุล
  • ที่อยู่
  • เบอร์โทร

มิจฉาชีพโทรหาพ่อแม่ของลูกค้า เรียกชื่อจริงและบอกที่อยู่ได้ถูกต้อง อ้างว่าลูกเกิดอุบัติเหตุและต้องโอนค่ารักษาด่วน ข้อมูลจริงทำให้เหยื่อไม่ทันสงสัย

ครอบครัวโอนเงินให้คนร้าย และมักตามคืนไม่ได้

2แก๊งคอลเซ็นเตอร์แอบอ้างเป็นเจ้าหน้าที่

  • เลขบัตรประชาชน
  • วันเกิด
  • ที่อยู่ตามบัตร

คนร้ายอ้างเป็นตำรวจหรือเจ้าหน้าที่รัฐ อ่านเลขบัตรและวันเกิดให้ฟังเพื่อยืนยันตัวตน แล้วบอกว่าบัญชีพัวพันคดีฟอกเงิน ต้องโอนเงินไปบัญชีเพื่อ "ตรวจสอบ"

เหยื่อเชื่อเพราะคนร้ายรู้ข้อมูลที่ควรมีแค่หน่วยงานรัฐ

3สวมรอยเปิดบัญชีหรือขอสินเชื่อ

  • เลขบัตรประชาชน
  • วันเกิด
  • สัญชาติ

ข้อมูลตามบัตรถูกใช้ยืนยันตัวตนกับบริการที่ตรวจสอบหละหลวม เพื่อเปิดบัญชีม้า สมัครบริการ หรือขอสินเชื่อในชื่อเจ้าของข้อมูล

หนี้และคดีตามมาที่เจ้าของข้อมูลซึ่งไม่รู้เรื่องเลย

4ข่มขู่หรือเลือกปฏิบัติจากข้อมูลอ่อนไหว

  • ผลตรวจสุขภาพ
  • กรุ๊ปเลือด
  • ศาสนา

ข้อมูลสุขภาพ โรคประจำตัว หรือประวัติคดีถูกใช้ขู่กรรโชก หรือทำให้ถูกปฏิเสธงานและประกัน

ความเสียหายต่อชีวิตและชื่อเสียงแก้คืนไม่ได้

ทำไมองค์กรต้องใส่ใจ: กฎหมายบังคับ และอันตรายจริง

ถ้าพนักงานคนหนึ่งวางข้อมูลลูกค้าลงในแชต AI แล้วข้อมูลหลุด ความรับผิดอาจไม่จบที่พนักงาน บริษัทในฐานะผู้ควบคุมข้อมูลส่วนบุคคลอาจต้องรับผิดด้วย ทั้งทางแพ่ง ทางอาญา และค่าปรับทางปกครอง ตามข้อเท็จจริงและองค์ประกอบความผิดของแต่ละกรณี

ข้อมูลอ่อนไหวตาม PDPA มาตรา 26

พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 กำหนดให้ข้อมูลกลุ่มนี้ต้องได้รับความยินยอมโดยชัดแจ้งก่อนเก็บ ใช้ หรือเปิดเผย เว้นแต่มีข้อยกเว้นตามกฎหมาย ส่วนข้อมูลตามบัตร เช่น ที่อยู่ วันเกิด และสัญชาติ เป็นข้อมูลส่วนบุคคลที่ใช้สวมรอยได้ง่าย Gate จึงซ่อนให้เช่นกัน

  • เชื้อชาติ เผ่าพันธุ์
  • ความคิดเห็นทางการเมือง
  • ศาสนาและความเชื่อ
  • พฤติกรรมทางเพศ
  • ประวัติอาชญากรรม
  • ข้อมูลสุขภาพ
  • ความพิการ
  • สหภาพแรงงาน
  • ข้อมูลพันธุกรรม
  • ข้อมูลชีวภาพ

หน้าที่ขององค์กรตามกฎหมาย

มาตรา 37(1)

ต้องมีมาตรการรักษาความมั่นคงปลอดภัยที่เหมาะสม ป้องกันการสูญหาย การเข้าถึง ใช้ เปลี่ยนแปลง หรือเปิดเผยข้อมูลโดยมิชอบ

มาตรา 37(4)

เมื่อข้อมูลรั่วไหล ต้องแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) โดยไม่ชักช้าภายใน 72 ชั่วโมงนับแต่ทราบเหตุเท่าที่จะทำได้ เว้นแต่เหตุนั้นไม่มีความเสี่ยงที่จะกระทบสิทธิและเสรีภาพของบุคคล และแจ้งเจ้าของข้อมูลพร้อมแนวทางเยียวยาหากมีความเสี่ยงสูง

มาตรา 40

ผู้ประมวลผลข้อมูลต้องมีมาตรการรักษาความปลอดภัยและแจ้งเหตุต่อผู้ควบคุมข้อมูล ผู้ให้บริการ AI อาจเป็นผู้ประมวลผลหรือผู้ควบคุมข้อมูลก็ได้ ขึ้นกับลักษณะบริการและการใช้ข้อมูลจริง องค์กรจึงต้องประเมินบทบาท และรู้ว่าส่งข้อมูลอะไรไปให้ใคร

บทลงโทษเมื่อข้อมูลหลุด

ประเภทมาตราโทษ
ทางแพ่ง77, 78ชดใช้ค่าเสียหายที่เกิดขึ้นจริง แม้ไม่ได้จงใจหรือประมาทเลินเล่อ และศาลสั่งค่าสินไหมเชิงลงโทษเพิ่มได้ไม่เกิน 2 เท่า
ทางอาญา79ใช้หรือเปิดเผยข้อมูลอ่อนไหวโดยมิชอบ จำคุกไม่เกิน 6 เดือน หรือปรับไม่เกิน 500,000 บาท หากเพื่อแสวงหาประโยชน์ จำคุกไม่เกิน 1 ปี หรือปรับไม่เกิน 1,000,000 บาท
ผู้บริหาร81กรรมการหรือผู้บริหารที่สั่งการหรือละเลยจนเกิดความผิดของนิติบุคคล ต้องรับโทษด้วย
ทางปกครอง82–84ปรับสูงสุด 1, 3 และ 5 ล้านบาทตามประเภทความผิด เช่น ไม่จัดมาตรการรักษาความปลอดภัยหรือไม่แจ้งเหตุ (มาตรา 83) และละเมิดข้อมูลอ่อนไหว (มาตรา 84)

โทษเหล่านี้ใช้จริงแล้ว ในปี 2567 สคส. เผยแพร่ว่าได้สั่งปรับบริษัทเอกชนรายหนึ่ง 7 ล้านบาท จากเหตุข้อมูลลูกค้ารั่วไหลและถูกนำไปใช้หลอกลวง

ถ้าพนักงานทำข้อมูลลูกค้าหลุด จะเกิดอะไรขึ้นกับบริษัท

  1. พนักงานต้องรับผิดชอบ ถูกสอบสวนทางวินัย และอาจถูกดำเนินคดีหากเปิดเผยข้อมูลโดยมิชอบ
  2. บริษัทต้องแจ้ง สคส. ภายใน 72 ชั่วโมงนับแต่ทราบเหตุ (เว้นแต่ไม่มีความเสี่ยงต่อเจ้าของข้อมูล) และต้องบอกได้ว่าข้อมูลอะไร ของใคร ถูกส่งไปที่ไหน ถ้าตอบไม่ได้ก็ประเมินความเสี่ยงไม่ได้
  3. ลูกค้าฟ้องเรียกค่าเสียหาย บริษัทอาจต้องรับผิดแม้ไม่ได้ตั้งใจ และอาจเสียค่าสินไหมเชิงลงโทษเพิ่ม
  4. ถูกตรวจสอบและปรับ หากพบว่าไม่มีมาตรการป้องกัน ไม่มีการสำรองข้อมูล ไม่มีบันทึกการประมวลผล หรือไม่แจ้งเหตุ อาจถูกปรับทางปกครองหลายล้านบาท
  5. ความเชื่อมั่นหายไป ลูกค้าและคู่ค้าเลิกไว้ใจ ซึ่งมักแพงกว่าค่าปรับ

ระบบบริหารความมั่นคงปลอดภัยสารสนเทศ มาตรการ A.8.11 Data masking และ A.8.12 Data leakage prevention ตรงกับสิ่งที่ Gate ทำ รวมถึง A.5.34 การคุ้มครองข้อมูลส่วนบุคคล

ISO/IEC 27701:2025

ระบบบริหารจัดการข้อมูลส่วนบุคคล (PIMS) ฉบับ 2025 เป็นมาตรฐานที่ใช้ได้โดยลำพัง กำหนดการจัดการข้อมูลส่วนบุคคลทั้งในฐานะผู้ควบคุมและผู้ประมวลผล

ISO/IEC 42001:2023

ระบบบริหารจัดการ AI กำหนดให้องค์กรควบคุมข้อมูลที่ใช้กับ AI และประเมินความเสี่ยงต่อบุคคล

ซ่อนก่อนส่ง

ลดโอกาสที่ข้อมูลลูกค้าจะออกนอกองค์กรตั้งแต่ต้นทาง

หลักฐานประกอบการสอบสวน

audit log บอกว่าข้อมูลประเภทใดถูกส่งไปผู้ให้บริการรายใดเมื่อไร โดยไม่เก็บเนื้อหา ช่วยประกอบการประเมินเหตุ แต่ไม่ใช้แทนการประเมินเหตุทั้งหมด

บล็อกข้อมูลมาตรา 26

ข้อมูลอ่อนไหวคู่กับตัวบุคคลไม่ถูกส่งออกไปตามนโยบายเริ่มต้นของ FirmAlways กฎหมายไม่ได้ห้ามทุกกรณี องค์กรปรับได้ตามฐานทางกฎหมายที่มี

สรุปเพื่อความเข้าใจ ไม่ใช่คำแนะนำทางกฎหมาย Gate ช่วยลดความเสี่ยงและเป็นหลักฐานประกอบมาตรการ แต่ไม่ได้ทำให้องค์กรผ่าน PDPA หรือได้รับการรับรอง ISO โดยอัตโนมัติ ข้อมูลที่แทนด้วย placeholder ที่คืนค่าได้ยังถือเป็นข้อมูลส่วนบุคคล (pseudonymisation) กรุณาตรวจสอบตัวบทและปรึกษาที่ปรึกษากฎหมาย

ติดตั้ง FirmAlways Gate

สำหรับนักพัฒนาและผู้ดูแลระบบ ต้องมี Python 3.11 ขึ้นไป หรือ Docker ถ้าใช้ AI ผ่านเว็บอย่างเดียว ติดตั้ง FirmAlways Personal ง่ายกว่า ไม่ต้องใช้ Terminal

สคริปต์ติดตั้ง

curl -fsSL https://firmalways.meapplication.co.th/install.sh | sh

สคริปต์ติดตั้งเวอร์ชันล่าสุดด้วย uv, pipx หรือ pip อ่านสคริปต์ก่อนรัน หรือใช้สคริปต์เดียวกันจาก GitHub release

curl -fsSL https://github.com/firmalways/gate/releases/latest/download/install.sh | sh

Docker

docker run --rm -p 8787:8787 -e FIRMALWAYS_GATE_API_KEY=change-me \
  -v "$PWD/policy.toml:/etc/firmalways/policy.toml:ro" ghcr.io/firmalways/gate

ลองดูว่า AI จะได้รับอะไร

firmalways-gate scan "ลูกค้าคุณสมชาย ใจดี เลขบัตร 1101700203611"

ใช้กับแอปที่มีอยู่

from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8787/v1", api_key="<FIRMALWAYS_GATE_API_KEY>")

ใช้ได้กับ OpenAI, Azure OpenAI ในบัญชีของคุณเอง, endpoint ที่รองรับ OpenAI API และโมเดลในเครื่อง เช่น Ollama ดูวิธีตั้งค่าทั้งหมดใน README ส่วนผู้ใช้เว็บ ChatGPT, Claude และ Gemini ใช้ FirmAlways Personal

สิ่งที่ FirmAlways Gate รองรับ

  • ติดตั้งในเครื่องหรือ cloud ของคุณ Gate ไม่ติดต่อเซิร์ฟเวอร์ของเราเลย
  • ถ้าตรวจข้อความไม่สำเร็จ จะไม่ส่งต่อ ไม่มีการปล่อยข้อมูลออกไปแบบไม่ได้ตรวจ
  • บันทึก audit เฉพาะจำนวนและประเภทข้อมูล ไม่บันทึกข้อความ คำตอบ หรือค่าจริง
  • ค่าที่ถูกซ่อนเก็บอยู่ในหน่วยความจำของคำขอนั้นเท่านั้น แล้วหายไป
  • key ของผู้ให้บริการ AI อยู่ที่ Gate แอปของพนักงานไม่ต้องรู้
